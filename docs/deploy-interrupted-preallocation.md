# Interrupted preallocation custody

`interrupted-preallocation-cleanup-v1` is a launch-only reconciliation for two
specific canceled operations: native cloud smoke whose complete campaign was
released before any guest allocation, and the ordinary backend structural npm
route whose native supervisor reaped every TERM target. It supplies no task,
runtime, financial cleanup, refund or settlement credit.

Use the existing cycle `reconcile --occurrence <original-request-token>
--proof <proof.json> --plan <frozen-plan> --state-dir <original-state-dir>`
command only after independently verifying the evidence. The token must select
the exact latest receipt in the terminal interrupted attempt. No original
request, receipt, failed case, cancellation flag, timestamp, null adapter or
cleanup reference is changed. Other reconciliations remain owned and retained.

The proof contains `kind`, canonical original Git `root`, `confirmed_at`,
`observed_by`, and `files` mapping absolute regular original paths to SHA256.
Bind request/receipt/stdout/stderr and all consumed evidence; every supplied
file is rehashed. The stored execution gate is checked with `preserve_contract`
on every subsequent ownership check, including after source refresh.

For static structural TERM, bind the original `output.log.process.json`.
The exact command is `npm run test:structural`, cwd `back-end`, without a remote
or isolated worker. Genuine supervisor evidence must show exit -15, the child
reaped with wait status 15, every TERM target reaped, no KILL, no remaining
processes or error. Fresh checks reject live recorded PIDs/process groups and
log holders. They do not require the entire source checkout to be idle.

Cloud proofs additionally name `publication_recovery`, `hub_consumers`,
`hub_retirement`, and `producer_files`. The latter maps the original source
paths `scripts/run-bench-fleet`, `scripts/run-bench-campaign.py`,
`scripts/lib/cloudbench-env.sh`, and `agents/benchmarks/hub_upload.py` to bound
file copies. Their bytes must equal Git objects at the original receipt SHA;
preserve copies if later source changes would replace those files.

Every requested task must have its exact failed/143 parent, failed rootless
INFRA_ERROR projection and native zero-call counters. Canonical and local
teardown seals must match the original lifecycle; all allocation ledgers and
classes must be empty, ownership registries absent, and recursive traversal
must find no allocation/admission/runtime marker or symlink. Missing provenance
is admitted only in this entirely unallocated case. Any mixed or allocated
cohort requires its normal full provenance/runtime/provider/payment workflow.

Preserve the original campaign summary, final group record and bad publication
ACK. Publication recovery must use a separate directory containing the exact
original copies, native `hub_upload.py --upload-final` owner/result receipt,
unchanged final record, successful matching ACK and terminal publisher evidence.
The existing native campaign projection/ACK validator is rerun. Rehashing the
old ACK or inventing an adapter/result is never a recovery procedure.

Bind every original Hub owner, the actual native `.owner.terminal` receipt,
the parent's exact retirement receipt and complete terminal borrower boundary.
Fresh checks require the whole old namespace to have no process/file consumer
or live Hub socket. Dead startup PIDs alone are insufficient. This validator
never signals a process or invokes provider, database or guest operations.

Confirmation follows the later native campaign, publication and Hub retirement
times. An outer canceled receipt may finish earlier; its original time remains
unchanged. Reconciliation can release launch eligibility only. Original failed
outcomes and all older excluded resources and financial/runtime debts survive.
