# Explicit optional AgentCard election after selection


The existing `/deploy` AgentCard election can also be recorded at quiescent
TRIAGE without resetting a cycle. Generate the new plan with the existing
`--skip-agentcard "<explicit operator reason>"` option. Refresh retains all
other gate/check contracts and every original attempt. This is a selected
coverage omission, never a task pass or a cleanup waiver.

An already started, incomplete lane requires `refresh --proof <custody.json>`
using `local-agentcard-omission-custody-v1`. The native validator requires the
original request/result/receipt and complete native task inventory, exact
original-source policies, archived originals with authenticated readback and
member restoration, verified physical closure, exact captured provider debt,
known loss, continuing accountability and each pending occurrence's RCA.
Original UNVERIFIED outcomes, failed financial cleanup and owners remain intact.
Other gates and assigned repairs cannot use this path. No new card or reclaim
operation is performed by selection or custody validation.

After merge, `accept-omitted-custody --input <acceptance-proof.json>` records a
different devbox's exact operational custody acceptance and independent archive
recovery. Hash-bind both its native start receipt (thread and devbox identity)
and completed result (execution identity, turn and acceptance hash). `complete` and `verify --require-resolved` remain blocked until that
acceptance exists. It supplies no task, native release or financial-settlement
credit. Report the elected lane as SKIPPED alongside its original actual
outcomes and outstanding liabilities.
