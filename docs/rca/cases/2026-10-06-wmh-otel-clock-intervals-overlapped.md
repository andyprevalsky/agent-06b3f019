## Problem

The rebuilt index contained all 179,169 canonical tool observations but also
280 empty native Steps. The audit is retained in
`.context/world-model/native-index-audit.json`. Empty rows were generated by
upstream ingestion; they were not completed archived results. The user requires
real completed observations only. The currently running diagnostic loaded that
original index before this independent audit discovered the defect.

## Diagnosis

The path is completed archived pairs → transitions_to_otel_spans → native
start-time/span-ID sort → pending-action pairing → serving index. Each exported
pair used clocks at offsets 2i, 2i+1, 2i+2, 2i+3. Thus observation i and action
i+1 received identical start clocks when their source millisecond matched.
The native hash tie-break could place the next action before the prior result,
flushing an empty Step and attaching that prior result to the wrong action.

Captured row 11158 from root 62a1467d-6975-48e8-85cd-7524e53f0e5b has exactly
this source neighborhood. The observation for action 297ee66ee4b17595 ties with
next action 0284fe9b7f35970a at 1783099905246000020. Native order is
chat-chat-tool-tool although source pairs are complete. Evidence is in
`.context/wmh-otel-timestamp-boundary-evidence.json`.

The permanent native-adapter reproduction covers 27 distinct action/result
pairs with equal, regressing, unknown, and zero original timestamps. Before
repair, its unchanged command failed with the fabricated-empty-Steps assertion
in `.context/wmh-native-pairing-red.log`. The five explicit hypothesis fields
are in `.context/wmh-native-pairing-hypothesis.json`.

Archive searches used `WMH empty observation span timestamp sort` and `OTel
action observation overlapping timestamps pairing`. The blank-prediction and
full-build JSONL cases are relatives at different boundaries, not this cause.
Adversarial review confirmed the actual upstream sort and pending-action flush,
exact source evidence, and permanent action/result/state/order assertions.

## Solution

Allocate one monotonic four-clock interval per completed pair. This eliminates
both overlapping timestamps and interleaving after clock regressions without
changing any canonical action, observation, state, or original timestamp.
Increment export schema to 11 so cached older projections are invalidated.
The repair simplifies the clock allocation to one cursor and adds no serving
path, LLM instruction, or synthetic observation. Cost is linear in projected
steps and constant extra state per trajectory, independent of live agent count.

The identical isolated command passed in `.context/wmh-native-pairing-green.log`.
The deploy-owned full world-model-harness runner passed in 2.5 seconds in
`.context/wmh-native-pairing-owning-green.log`, including all 27 exact decoded
payloads and state/order checks. The corrected uncapped full index is being
prepared separately from the running diagnostic's immutable in-memory index,
using all existing completed source pairs and the existing bounded native
index refresher. No archive input or record is dropped. The corrected full build finished in 210.995 seconds: 12,519 trajectories
and exactly 179,169 indexed observations. A complete 23.098-second audit compared
every corrected Step with the original archived action/observation/state/order
and verified matrix shape (179169, 512), with zero empty native observations.
Evidence is `.context/world-model-grounded/canonical-pair-audit.json`. Matching
live conformance, the exact fundraiser outcome with this corrected index, and
final replay verification remain pending; proxy proof is not outcome proof.

## Reusable lesson

Reserve a disjoint causal clock interval for every projected action/result pair
and test exact native ingestion under equal and regressing source clocks.
