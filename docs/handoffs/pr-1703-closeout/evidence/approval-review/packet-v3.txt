Before:
  Asked to "move to and click" a control like a person, the browser
  agent (moonshotai/kimi-k3, pool rose-1-oss) says "there's no pure
  mouse-move tool" and uses `drag` (press-hold-release) to fake pointer
  movement. The raw-CDP drag presses at a teleported pointer, which FCaptcha
  reports as "Click injected with no pointer trajectory (1 teleport clicks)".
  Later, moving toward the submit button, it sends drag({"end_x":480,
  "end_y":408,"steps":20}), which is rejected, and repeats that call
  177 times until the 420 s task timeout.
────────────────────────────────────────────────────────────────
After:
  Same page and task: the agent calls `hover` to move the pointer without
  pressing, then `click`; it makes no drag, the task completes in about
  140 s, and FCaptcha returns no vision_ai/teleport detection. Any drag that
  is still needed (sliders) presses only after the humanizer has moved the
  pointer to its start. Unchanged: the task, evaluator, timeout and ratchet.
────────────────────────────────────────────────────────────────
How:
  Adds a `hover` tool schema and description, edits the click,
  click_coordinates, drag and evaluate tool descriptions to match the
  runtime, and routes drag through the existing humanizer.drag_between.
────────────────────────────────────────────────────────────────
TL;DR:
  Approving gives every browser agent a native pointer-only `hover` tool
  and accurate click/drag text, which stops the drag-as-movement misuse
  behind both webdecoy failure modes.
